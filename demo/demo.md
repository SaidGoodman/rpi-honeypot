# Сценарий демонстрации

> Все команды выполняются **только против своей Raspberry Pi в своей изолированной сети**.
> Сканирование и подбор паролей к чужим устройствам без разрешения владельца незаконны
> (ст. 272 УК РФ «Неправомерный доступ к компьютерной информации»).

## Стенд

```
[Raspberry Pi] ── HDMI ──> [монитор / проектор]       страница мониторинга в режиме киоска
      │
      └── Wi-Fi «NAS-Backup» (192.168.50.0/24, раздаёт сама Pi)
              │
       [ноутбук атакующего]                            nmap, hydra, браузер
```

| Что | Адрес |
|---|---|
| Raspberry Pi (ловушка) | `192.168.50.1` |
| Страница мониторинга | `http://192.168.50.1:5000` |
| Настоящий SSH администратора | `ssh -p 2222 <пользователь>@192.168.50.1` |

Если стенд собран на своём роутере, вместо `192.168.50.1` подставьте адрес Pi
(его показывает `install.sh` в конце или команда `hostname -I` на Pi).

## Что нужно на ноутбуке атакующего

`nmap` и `hydra`. Проще всего взять Linux:

- **Kali Linux** в VirtualBox с сетевым адаптером в режиме «Сетевой мост» (bridged) или запущенная с флешки: всё уже установлено;
- любой Linux: `sudo apt install nmap hydra`;
- на Windows `nmap` ставится с [nmap.org](https://nmap.org/download.html), `hydra` удобнее запускать в WSL или в Kali.

Подключите ноутбук к Wi-Fi `NAS-Backup` и проверьте связь: `ping 192.168.50.1`.

## 0. Перед началом

На экране Pi открыта страница мониторинга. Если хотите начать с пустой страницы,
очистите лог на Pi:

```bash
sudo truncate -s 0 /var/log/opencanary.log
```

## 1. Сканирование портов

```bash
sudo nmap -sS 192.168.50.1
```

Что видим:
- в терминале nmap «открытые» порты 21, 22, 23, 80 (могут быть видны и 2222 с 5000: это настоящий SSH и сама страница);
- на странице появляются события «Порт: SYN-пакет» на разные порты, IP ноутбука
  попадает в «Обнаруженные атаки» с пометкой **сканирование портов**.

Дополнительно можно показать, как ловушка выдаёт себя за старый сервер:

```bash
sudo nmap -sV -p 21,22,23,80 192.168.50.1   # версии сервисов: «OpenSSH 7.4p1 Debian», «ProFTPD 1.3.5»
sudo nmap -O 192.168.50.1                   # определение ОС: событие «Порт: nmap OS»
sudo nmap -sX 192.168.50.1                  # XMAS-сканирование: событие «Порт: nmap XMAS»
```

## 2. Подбор пароля к SSH

```bash
hydra -L demo/users.txt -P demo/passwords.txt -t 4 -V ssh://192.168.50.1
```

Что видим:
- hydra перебирает 10 логинов × 12 паролей = 120 комбинаций и не находит ни одной: ловушка отвергает любой пароль;
- на странице идёт поток «SSH: попытка входа» с логинами и паролями, в «Частых логинах»
  и «Частых паролях» растут счётчики, IP получает пометку **подбор пароля**.

## 3. Другие сервисы (по желанию)

```bash
hydra -L demo/users.txt -P demo/passwords.txt -t 4 ftp://192.168.50.1
hydra -L demo/users.txt -P demo/passwords.txt -t 4 telnet://192.168.50.1
```

Страница входа в «сетевое хранилище»: откройте в браузере `http://192.168.50.1`
и попробуйте войти с любым логином и паролем. На странице мониторинга появится
событие «HTTP: попытка входа» с введёнными данными.

## 4. Что рассказать

- Ловушка не пускает внутрь ни при каком пароле и ничего не выполняет: это ловушка низкого уровня взаимодействия (low interaction).
- Обычным пользователям к ней обращаться незачем, поэтому любое обращение уже подозрительно, ложных срабатываний почти нет.
- Настоящий SSH к Pi работает на порту 2222 только по ключу, подобрать к нему пароль нельзя.
- Правила обнаружения: ≥5 попыток входа с одного IP за 60 секунд — подбор пароля; ≥10 разных портов с одного IP за 60 секунд или специальный пакет nmap — сканирование.
